## 1. 产品概述

XPlay 是一个用 Flutter 编写的 TikTok 风格 X/Twitter 客户端，专注**视频与图片的沉浸式浏览**。核心价值：

- 用"上下滑"的全屏体验替代传统时间线列表
- 聚合**订阅用户**的媒体内容，自动抓取、缓存、离线可看
- 通过可调参数的**发现算法**（混合新旧内容、多样性控制、未见创作者加权）生成个性化信息流
- 本地 SQLite 缓存 + 后台同步，减少网络请求、提升加载速度

### 技术栈

| 组件 | 技术 |
|------|------|
| 框架 | Flutter 3.44.9 / Dart 3.12.2 |
| 状态管理 | Riverpod |
| 视频播放 | media-kit (libmpv) + media_kit_video |
| 数据库 | SQLite (sqflite) |
| 图片缓存 | flutter_cache_manager + cached_network_image |
| 网络 | http + 自定义 Twitter GraphQL 客户端（x.com 内部 API） |
| WebView | webview_flutter + webview_cookie_manager_plus（登录/捕获） |
| 持久化 | shared_preferences（设置、query ID、更新状态） |
| 更新检查 | package_info_plus + GitHub API |

## 2. 应用启动与架构

`lib/main.dart`

启动流程（`main()`）：

1. `MediaKit.ensureInitialized()` — 初始化视频播放器
2. 并行初始化三个核心组件：
   - `TwitterAccount.init()` — 从数据库加载已保存账号
   - `QueryIdResolver.init()` — 加载持久化的 GraphQL query ID
   - `Repository.database` — 打开 SQLite 数据库
3. 进入主界面后自动启动 `BackgroundSync`（后台同步）

生命周期处理：

- 应用**从后台恢复**时：重置 API 请求队列、重启后台同步（`main.dart:38`）
- **同步设置变更**（间隔/批次/修剪阈值）时：自动重启后台同步（`main.dart:46`）

主题：Material 3、深色模式、黑色背景、蓝色主色。

## 3. 登录与账号

`lib/features/auth/login_screen.dart` · `lib/core/client/account_provider.dart` · `lib/core/database/entities.dart`

- **登录方式**：内置 WebView 打开 `https://x.com/i/flow/login`，使用移动端 User-Agent，用户直接在 X 官方登录页输入账号密码
- **凭证捕获**：登录成功后跳转到 `x.com/home`，从页面 DOM 提取 `screen_name`，通过 Cookie Manager 读取 `ct0` 等 Cookie，组装 `Cookie`/`authorization`/`x-csrf-token` 请求头
- **账户存储**：`Account`（id/ct0、screenName、restId、authHeader JSON）存入 SQLite `accounts` 表；支持多账号入库，启动时默认使用第一个账号
- **退出登录**：设置 → 系统 → 退出登录，删除数据库中的账号记录并清空登录态

未登录状态：媒体页、订阅页显示 "Login to X" 引导按钮。

## 5. 媒体信息流（TikTok 式）

`lib/features/feed/tiktok_feed_screen.dart` · `lib/features/player/player_pool_provider.dart` · `lib/features/player/widgets/media_container.dart`

### 5.1 浏览方式

- **全屏纵向翻页**（PageView），上下滑动切换内容
- 每次翻页自动标记当前推文为"已播放"（`Repository.markMediaAsPlayed`），用于发现算法与"避免已看内容"
- 接近列表尾部（`lazyLoadThreshold` 条剩余）时自动触发 `fetchMore()` 加载下一批

### 5.2 播放器池与预加载（核心体验优化）

`player_pool_provider.dart`

- 维护一个 `Player` 实例池，按推文 ID 索引
- **预热**：当前页 ±1 到 +3 范围内的视频提前 `player.open()`（不播放），图片则 `precacheImage` 预缓存 → 滑到即播、无缓冲
- **清理**：只保留当前可视范围内的实例，其余 `dispose()` 释放内存
- 硬件加速开启；应用退出时统一释放全部实例

### 5.3 视频播放行为

- **自动播放**：仅当该页可见时 `play()`，离开自动 `pause()`（可关闭）
- **点击暂停/恢复**：非全屏时点击画面切换播放状态
- **播放结束动作**（`videoEndAction`，默认 playNext）：
  - `pause` — 停在末尾
  - `replay` — 回到开头重播
  - `playNext` — 自动滑到下一个视频
- **播放失败处理**：
  - 按 `playbackRetryLimit` 次数自动重试（重新 `open` 媒体）
  - 仍失败则显示错误画面，并在 `autoSkipDelaySeconds` 秒后自动跳到下一条
- **全屏**：进入全屏时根据视频宽高比自动判断横竖屏（`width/height > 1` 横屏，锁定 landscapeLeft/Right；否则竖屏），退出时恢复竖屏
- **进度条**：画面底部 2px 白色细进度条（不拦截触摸）
- 全屏控制栏：播放/暂停、进度条、时间、**点赞按钮**、退出全屏

### 5.4 图片浏览

- 单图：自适应 `BoxFit.contain` 全屏展示
- 多图：横向 PageView 滑动浏览，底部圆点指示器

### 5.5 纯文字推文

无媒体时以渐变卡片 + 居中大字号文本展示（`text_tweet_card.dart`）。

### 5.6 推文信息覆盖层

`lib/features/feed/widgets/tweet_text_overlay.dart`

- 底部渐变遮罩：作者头像（点击进资料页）、`@用户名`（点击进资料页）、已订阅蓝勾、订阅按钮（+）、发布时间
- 推文正文：最多 3 行，点击展开/收起；超过 100 字显示 "Read more"
- **智能链接**：`#话题`（浅蓝高亮，点击进入话题流）、`@用户`（浅蓝，点击进资料页）
- 右侧操作栏：点赞（含数量，红心）、评论（弹出回复面板）、分享（占位提示 "coming soon"）、全屏/退出全屏

### 5.7 调试覆盖层

开启"覆盖层来源信息"后，每条内容左上角显示调试卡片：类型（VIDEO/IMAGE）、来源（API/Cache）、ID 尾 8 位、媒体数、本条播放次数、该作者累计播放次数、时间戳。

## 6. 内容发现引擎（推荐算法）

`lib/core/client/discovery_engine.dart` · `lib/features/feed/feed_provider.dart`

### 6.1 数据流水线

信息流 = **本地缓存池** + **API 新鲜内容** 混合生成：

1. **冷启动**（Stage 1）：立即从 SQLite 取 `loadBatchSize × dbCandidateMultiplier` 条缓存候选（"Cache" 来源），同时预热前 3 个视频 → 秒开
2. **后台刷新**（Stage 2）：按 `fetchStrategy` 从 API 拉取新鲜内容（"API" 来源）并写入缓存
3. **混合**：`DiscoveryEngine.interleave(fresh, cached, freshMixRatio)` 按比例交叉排列（默认 30% 新 / 70% 已存）
4. **多样性处理** → 输出最终信息流

刷新时**保护当前正在看的视频**（列表前 2 条不被算法换位，避免正在播的内容跳走）。

### 6.2 去重策略

- 推文 ID 去重（当前列表滑动窗口 `mediaDeduplicationWindow` 条）
- 媒体 URL 去重：同一媒体在第一张图/视频地址维度去重
- SQLite 层：按 `media_key` 去重，同 key 的推文若已播放则不再推荐

### 6.3 未见创作者加权（Unseen Boost）

`applyUnseenSubscriptionBoost`

- 统计每个作者在你这里的累计播放次数（`getPlayedCountsByUser`）
- 在 `unseenBoostLookahead` 前瞻窗口内，把播放次数最少的创作者内容上移到当前位置，优先展示"你很少看的人"（避免与前一作者重复）

### 6.4 多样性饱和（Saturation）

`applySaturation`，多轮扫描（`maxSaturationPasses`）：

- **作者饱和**：同一作者在 `saturationWindow` 窗口内最多出现 `saturationThreshold` 次（默认 2）
- **媒体饱和**：同一媒体在窗口内最多出现 `mediaSaturationThreshold` 次（默认 1）
- **硬规则**：不允许相邻两条同作者、同媒体
- 违规时向前查找合法替换项并交换；`maxSaturationSwaps` 为安全上限

### 6.5 加载更多（fetchMore）

滑到底部时循环执行，直到凑够 `minNewTweetsThreshold` 条新内容：

1. 先从本地缓存池取未看过的新候选
2. 再打 API（用上一页 cursor 分页）
3. cursor 卡住/页翻完 → 轮换下一个订阅分块（`chunkRotationLimit` 上限），或失败重试（`apiRetryLimit`）
4. 全部候选随机打散后取 `loadBatchSize` 条追加到尾部，再次应用饱和算法

### 6.6 点赞（乐观更新）

`feed_provider.dart:toggleLike`

- 立即更新本地 UI（心形+计数），再调 X API `FavoriteTweet`/`UnfavoriteTweet`
- API 失败则**回滚**到原状态

## 11. 后台同步与数据

`lib/core/client/background_sync.dart` · `lib/core/database/repository.dart`

### 11.1 后台同步（BackgroundSync）

- 启动后立即执行一次 + 按 `syncInterval`（默认 15 分钟）周期执行
- 每次随机抽取 `syncBatchSize`（默认 10）个订阅用户，构造 `from:A OR from:B ... -filter:replies` 查询，用 trending 接口抓取最新媒体写入缓存
- 互斥执行（`_isSyncing` 防止并发）；订阅为空则跳过
- 429 限流自动等待 `cooldownDuration` 分钟

### 11.2 缓存修剪（prune）

- 启动 1 分钟后自动执行；阈值 `pruneThreshold`（默认 50000 条）
- 规则：删除 7 天前的数据；仍超限则按"最近播放/创建时间最旧"优先删
- 手动入口：设置 → 存储与缓存 → "清除已看元数据"（删除所有 played_count > 0 的记录，重置推荐池）

### 11.3 本地媒体缓存

- 媒体文件：flutter_cache_manager 自定义缓存（过期 7 天，最多 200 个对象），设置中可查看已用 MB、设置上限（100–2000 MB）、一键清空
- 元数据：`cached_media` 表记录每条推文，含播放次数、播放时间、最近推荐时间，用于算法

## 12. 设置中心

`lib/features/settings/settings_screen.dart` · `settings_provider.dart`

所有设置通过 shared_preferences 持久化。分组如下：

### 12.1 体验 → 播放与信息流

| 设置 | 默认 | 范围/选项 | 说明 |
|------|------|-----------|------|
| 内容策略 fetchStrategy | chronological | 6 种 | 订阅：最新/热门/趋势；为你推荐 (X)；关注列表 (X)；视频混音 (X) |
| 自动播放 | 开 | 开/关 | 视频可见时自动播放 |
| 视频播放结束后 | playNext | pause/replay/playNext | 见 §5.3 |
| 视频加载重试次数 | 1 | 0–5 | 播放失败重试上限 |
| 内容过滤（FilterChip 多选） | 全选 | VIDEO/IMAGE/TEXT | 信息流只显示选中类型；空集=全部 |
| 初始信息流大小 | 10 | 1–100 | 启动立即加载的视频数 |
| 滚动加载批次大小 | 20 | 5–100 | 到底部加载的新视频数 |
| 新旧内容混合比例 | 30% | 0–100% | 新内容/已保存内容占比 |

### 12.2 体验 → 发现与多样性

| 设置 | 默认 | 范围 | 说明 |
|------|------|------|------|
| 避免已看内容 | 开 | 开/关 | 隐藏已播放过的视频 |
| 未见创作者加权 | 开 | 开/关 | 多展示很少看到的创作者 |
| 创作者多样性 | 2 | 1–10 | 同一作者在窗口内最多出现次数 |
| 视频多样性 | 1 | 1–5 | 同一视频最大副本数 |
| 多样性窗口 | 10 | 5–100 | 算法回溯范围 |
| 严格去重 | 50 | 10–200 | 精确媒体键匹配回溯范围 |
| 发现范围 | 6 | 2–50 | 搜索深度（unseen boost lookahead） |
| 候选池大小 | 5 | 1–20 | 本地搜索空间倍数（×loadBatchSize） |

### 12.3 数据与存储 → 后台获取

| 设置 | 默认 | 范围 | 说明 |
|------|------|------|------|
| 刷新频率 | 15 分钟 | 1–120 | 后台检查新视频频率 |
| 刷新强度 | 10 | 1–50 | 每次检查的账户数 |
| 账户冷却时间 | 15 分钟 | 0–240 | 再次检查同一账户等待时间 |

## 16. 技术实现要点

### 16.1 X 内部 API 客户端

`lib/core/client/twitter_client.dart` · `twitter_account.dart`

- 直接调用 x.com 的 GraphQL 内部接口（`/i/api/graphql/{queryId}/{Operation}`）
- 请求头：Bearer token、账户 Cookie、`x-csrf-token`、`x-client-transaction-id` 等
- **限流保护**：全局串行队列（单请求进行中 + FIFO 等待队列）；收到 429 后按 `cooldownMinutes` 暂停全部请求
- **HTTP 缓存**：GET 响应可指定缓存时长（如关注列表缓存 1 小时），MD5 key + ffcache 磁盘缓存
- 支持的操作：SearchTimeline、TweetDetail、HomeTimeline、HomeLatestTimeline、MediaTabVideoMixer、Following、UserByScreenName、UserTweets、FavoriteTweet、UnfavoriteTweet

### 16.2 Query ID 运行时解析

`lib/core/client/query_id_resolver.dart`

X 会轮换 GraphQL query ID，硬编码会失效（404）。三层策略：

1. 内置社区快照 ID（离线可用）
2. **WebView 实时捕获**：隐藏的 1×1 透明 WebView 加载 x.com，注入 JS 钩子（重写 fetch/XHR）记录真实生成的 `/i/api/graphql/{id}/{op}` URL，持久化到 SharedPreferences 复用；捕获序列会依次访问搜索页、x.com、书签页以触发各类操作
3. 可选的远程 JSON 覆盖源（`remoteUrl`，当前未启用）

另带备选 ID 列表，请求 404 时按序重试。

### 16.3 事务 ID 生成

`lib/core/client/transaction_id_service.dart`

- 优先由隐藏 WebView 内嵌的 deobfuscated JS（移植自 twitter-tid 指纹算法）本地生成 `x-client-transaction-id`
- 本地失败时回退到外部生成服务（`x-client-transaction-id-generator.xyz`，2 秒超时）
- 部分设备上指纹生成会失败，但不影响核心功能（README 已知限制）

## 17. 已知限制

- 事务 ID 生成器在部分设备上失败（WebRTC/CSS 不可用），不影响核心功能
- 首次启动需等待 WebView 捕获序列完成（约 10–15 秒）才能正常加载媒体
- Query ID 可能再次过期，届时需重新安装或更新 `query_id_resolver.dart` 中的备选 ID
- 分享功能为占位（"coming soon"）
- 账号切换 UI 未实现（仅多账号入库、默认取第一个）
